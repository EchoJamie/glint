## 1. 实施路线与首版完成标准

先用最小输入法原型验证连续卷轴与 Touch Bar 的系统接入，确认窗口实现路径；再形成可日常输入的独立产品，补齐可视化设置和词库管理，最后完成持续试用与开源交付准备。

首版完整范围如下。阶段中可以先交付试用包，但不能因为中途能打字，就宣告已经完成整个项目。

| 能力 | 首版执行范围 |
| --- | --- |
| 中文输入 | 保留当前认可的全拼方案、候选排序及 Rime 学习行为；固定实际采用的方案、词库、插件和版本 |
| 中英文切换 | 保留纯拼音原样上屏后切换的体验；验证组合、焦点和重复提交边界 |
| 屏幕候选 | 紧凑、展开、连续滚动、编号、高亮、鼠标与键盘选择、长词和屏幕定位 |
| Touch Bar | 原生风格候选条、浏览、点按与取消、和屏幕共享选择结果、跨应用恢复 |
| 可视化设置 | 输入习惯、候选外观、当前方案与状态、恢复默认及高级配置入口；不要求日常编辑 YAML |
| 个人词库 | Rime 快照备份与合并恢复、原生文本格式批量导入导出、有效结果反馈 |
| 专业词库 | 支持与基线方案兼容的 Rime 扩展词典，导入、启用、停用、导出 |
| 云同步 | 可开启的 iCloud 同步，默认关闭：个人学习词典先行，用户配置随后；开关状态、进度、冲突与失败均需明确反馈 |
| 数据迁移 | 从鼠须管迁入选定配置和学习数据，使用新项目独立目录，不共享打开中的数据库 |
| 使用与交付 | 可重复构建、安装与卸载说明、可恢复的升级方式、依赖来源与许可证记录 |

长按 Caps Lock 大写锁定放到首版核心体验稳定之后，独立验证；不阻塞上述范围。低频分词问题继续仅留档。双拼迁移、联网热词、通用配置编辑器、插件市场和自动更新服务不进入本轮开发。云同步的范围限定为：通过 iCloud Drive 的普通文件夹同步个人学习词典与用户配置（见[决策记录 3.2](decisions.md#32-icloud-同步)）；CloudKit、iOS 端、第三方云盘和多人共享不纳入本轮。

长期词汇体验先延续现有 Rime 机制，检查迁移、学习和重新检索是否正常。短期测试不能证明永久记忆；只有实际发现问题后，才另行定位原因，不在本计划中先改排序算法。

## 2. 最小工程组织

采用独立仓库，按需取用鼠须管源码；参考仓库保持参考用途。主要代码使用 Swift，系统接入使用 InputMethodKit/AppKit，调用 librime 的现有 C API。

建议先保持一个输入法 App：输入源菜单打开同一 App 内的设置窗口，设置内容可用 SwiftUI 承载；不预先拆独立管理服务或常驻辅助进程。耗时工作离开界面主线程，Rime 会话、部署和词库维护按明确顺序执行；同一运行时和数据库不并发修改。

| 责任范围 | 主要职责 | 明确边界 |
| --- | --- | --- |
| 系统输入接入 | 会话、按键、预编辑、提交、焦点、光标位置和中英模式 | 不另做拼音解析和学习 |
| Rime 调用与候选状态 | 引擎生命周期、候选读取、代次、全局索引和统一确认 | 不重排候选，不建设通用多引擎接口 |
| 候选呈现 | 一种屏幕窗口实现及 Touch Bar 系统接入 | 共用同一候选来源，不复制选词状态机 |
| 设置与维护 | 选项读取、预览、保存、实际应用；词库导入导出和结果反馈 | 图形界面不直接修改打开中的用户数据库 |
| 构建与分发 | 依赖固定、资源打包、安装卸载、来源记录 | 构建不隐式安装，安装不覆盖鼠须管 |

这些是代码职责，不要求每一项建立独立包、框架或进程。优先采用现有机制，必要的少量数据结构用于候选身份和实际生效状态。

新产品使用独立的 bundle identifier、输入源 identifier、连接名、安装目录和用户数据目录。中英文名定为「流光」/ Glint，仓库名 `glint-ime`，起始版本号 `0.1.0`；**上述标识已全部确定**，具体取值见[决策记录 5.4 节](decisions.md#54-项目标识版权与签名)，开工时直接使用，无需再定占位名。版权行 `Copyright (C) 2026 EchoJamie <echojamieee@outlook.com>` 须在建仓库时写入源文件头。

首版只构建 **Apple Silicon（arm64）**，不构建 Intel、不做通用二进制；最低 macOS 版本不预设，由 M0/M1 实测记录（[D-14](decisions.md#2-已确定的方向)）。

## 4. 阶段、依赖与退出条件

工期为粗略工程投入区间，按一条主要开发线、可用测试设备和及时试用反馈估算，不是交付承诺，也不是当前已经消耗的时间。第 0 阶段结束后依据真实结果重估，尤其是 Touch Bar 跨应用接入。

| 阶段 | 工作与交付物 | 通过条件 | 粗估投入 |
| --- | --- | --- | --- |
| M0：技术原型 | 最小工程、候选与 Touch Bar 原型、系统接入记录、技术选型结论 | 能从真实 Rime 会话取得候选，屏幕与触控栏选择回到同一引擎；确定能满足卷轴的窗口路径 | 2–4 个开发日；若桥接受阻单独重估 |
| M1：日常输入底座 | 全拼资源、输入与切换、隔离数据、输入源图标与 app 图标、开发构建及试用安装 | 常用应用中可连续输入；预编辑、部分确认、中英切换无丢字和重复提交；能恢复使用鼠须管 | 3–5 个开发日 |
| M2：完整候选体验 | 规格中的屏幕卷轴、Touch Bar、布局、高亮与过期事件处理 | 两种呈现方式通过统一索引、连续浏览、取消与焦点切换验收 | 5–8 个开发日 |
| M3：可视化设置 | 输入、外观、状态与高级入口；预览和实际生效反馈 | 日常设置不必改文件，失败仍有可用配置，不打断正在输入的组合 | 3–5 个开发日 |
| M4：词库、同步与迁移 | 个人快照、文本交换、专业词库管理、鼠须管迁移入口；iCloud 个人词典同步；随后是配置同步（哈希基线、冲突检测、部署回滚） | 使用测试数据完整走通导入/导出/恢复；失败不损坏原数据，学习可跨重启保留；两台机器上验证双向同步收敛，冲突不静默覆盖 | 7–12 个开发日 |
| M5：长期试用与交付准备 | 跨应用问题修复、性能记录、安装卸载与升级演练、开源交付材料 | 核心需求无未解决阻断项；实体 Touch Bar 和真实应用完成验收；发布材料可复核 | 3–5 个开发日，另含 7–14 天日常使用观察 |

合计约 **23–39 个有效开发日**，外加日常使用观察窗口。观察可以与后半程修复重叠；不能在 M0 未验证前换算成固定发布日期。相对 1.0 版的 20–34 个开发日，增量来自 2026-09-24 纳入的 iCloud 同步，其中配置同步的冲突检测与部署回滚是主要部分。

主要依赖是 `M0 → M1 → M2 → M3 → M4 → M5`。M3 的页面草图和 M4 的格式梳理可以在候选开发期间推进，但配置应用与数据库操作必须等 M1 的生命周期管理明确。M4 内部也分先后：词典同步只需 M1 的数据隔离，配置同步还要等 M3 验证过的部署、生效确认与失败回滚机制，不能与词典同步同时开工。M0 的 Touch Bar 若遇到实际阻断，其他不依赖窗口选型的设计仍可继续，但不能将未验证的触控栏标为完成。

可以分别交付：M1 的开发测试包、M2 的输入体验试用版、M4 的功能完整试用版、M5 的首版交付候选。M1 测试包只是验证基础链路，不要求用户立即替换日常输入法。

## 5. 第一批任务：先回答决定架构的几个问题

按以下顺序开展 M0，避免一开始就建设完整设置界面或所有词库功能。

| 任务 | 具体工作 | 可检查的交付物 |
| --- | --- | --- |
| T0.1 基线与独立原型 | 记录实际使用的全拼方案及必要插件；准备独立工程和测试数据目录（引擎版本已锁定 librime 1.17.0） | 构建成功的最小输入法产物，依赖与环境清单，构建和安装相互分离 |
| T0.2 候选协议 | 接入全局索引读取、高亮和确认；覆盖同字不同候选、部分组句和旧会话事件 | 能检查候选身份及提交次数的离线用例；不读取真实个人词条作测试样本 |
| T0.3 公共候选窗口 | 用同一组长短候选验证紧凑/展开、追加保持位置、编号、Return/Escape 和焦点 | 每项成功/失败的记录，确定 IMKCandidates 能否承担屏幕窗口 |
| T0.4 Touch Bar 真正接入 | 在宿主输入会话中验证系统候选条显示、点按、取消、恢复及与屏幕并用 | 真实跨应用显示和选择证据；设置 App 中的自制触控条演示不算通过 |
| T0.5 锁定实现 | 公共屏幕组件不足时，验证最小 AppKit 滚动窗口，同时保留 Touch Bar 路径 | 只选定一种屏幕实现；删除未采用的产品运行分支，更新后续任务估算 |

M0 使用固定测试候选和隔离 Rime 数据，不对鼠须管现用目录做维护。Touch Bar 原型应在具备实体触控栏的 Mac 上验证；若开发机不具备硬件，先完成不依赖硬件的部分，硬件验证仍保留为未完成条件。

屏幕组件不符合交互规格时可以直接转 AppKit 方案；Touch Bar 跨应用链路未通过时，不能以改画一个自定义触控条代替。需记录确切失效场景、可行路径及对需求的影响，再据此调整计划，不盲目增加私有接口或常驻服务。

本轮只排计划。将来的真实宿主验证涉及注册和选择新输入源，应在隔离产物、明确步骤和回退方式准备好后安排；不要求重新开启已关闭的系统中文输入法。

## 6. 设置与词库任务的落地范围

### 6.1 设置窗口

建议分为四个日常入口：

| 页面 / 入口 | 第一版内容 |
| --- | --- |
| 输入 | 当前全拼方案及版本、中英文切换行为说明、少量常用标点选项；保留当前默认行为 |
| 候选外观 | 字体、字号、跟随系统/浅色/深色、使用示例词的实时预览；Touch Bar 跟随系统风格 |
| 词库与备份 | 个人数据备份恢复、个人文本交换、专业词库启停与导入导出、迁移入口 |
| 状态与高级 | 当前实际生效版本、应用进度与错误、打开配置和诊断目录、仅恢复本产品托管选项 |

设置只管理明确支持的键，保留其余自定义内容。界面需要说明某项由高级配置覆盖的情况，不用整文件重新序列化覆盖用户配置。高级文件与界面之间的冲突规则在 M3 开始时用具体样例核对。

外观类修改在安全时机直接刷新；涉及方案重部署的修改区分“已保存、等待输入结束、正在应用、已生效、失败”。以部署结果和运行时重新读取的状态确认生效，不能将文件保存成功作为完成。部署失败保留或恢复上一套可用配置。

打开设置窗口属于用户主动操作，返回原应用后应能继续输入。词库维护或重新部署先等待当前组合结束；维护期间明确反馈输入暂不可用或尚未应用，不偷偷确认/丢弃用户正在输入的内容。

### 6.2 词库交换与迁移

首版格式以锁定版本的 Rime 原生能力为准，降低转换和维护成本：

| 任务 | 首版格式与行为 | 必要核对 |
| --- | --- | --- |
| 个人学习备份与恢复 | Rime 原生用户词典快照；恢复以兼容词典的合并恢复为默认 | 词典身份、编码兼容、运行中数据库占用、失败保留原数据 |
| 个人词条文本交换 | 锁定版本词典工具支持的 UTF-8 原生文本格式；导入前展示目标与有效/无效条目 | 不将普通文本宣传成完整学习历史；编码与目标方案相符 |
| 专业词库 | 与基线方案兼容的 Rime `.dict.yaml` 扩展词典；保持独立启停，导出源词典及必要声明 | 导入依赖、编码、同名冲突和编译结果；不默认导入不相关方案或脚本 |
| 鼠须管迁移 | 预览将迁入的配置、方案依赖与学习数据，导入新目录 | 不覆盖原目录，不直接复制正在写入的数据库作为完整快照 |
| iCloud 个人词典同步 | 按 `installation_id` 分目录交换 Rime 原生快照文本，合并所有可见快照后再导出本机快照 | 两机 `installation_id` 必须不同；不同步 `.userdb` 数据库目录；快照落盘用临时文件加原子改名，合并后核对条目数 |

CSV、搜狗/百度专有格式转换、在线词库商店暂不纳入。无效条目、依赖缺失或同名冲突必须在写入前给出可理解的结果，不能静默覆盖。专业词库停用只停止参与候选生成，不联动删除个人学习记录。

词库工具按操作需要调用，不新增常驻数据库服务。使用 Rime 的同步/快照机制或确认数据库已安全关闭后操作；所有恢复、导入先在隔离测试数据上验证。自动学习仍依靠日常输入，词库界面不是让用户逐条登记常用词。

### 6.3 iCloud 同步的实施顺序

机制、冲突语义与必须排除的文件见[决策记录 3.2](decisions.md#32-icloud-同步)；本节只定实施顺序与边界。

分两步推进，不作为一次交付：

1. **个人学习词典同步**——依赖 M1 的独立数据目录和独立 `installation_id`。工作含开关与状态、快照搬运（原子写、条目数核对）、未下载占位文件的处理、失败与冲突的反馈。
2. **用户配置同步**——在 M3 验证过部署、生效确认和失败回滚之后再开工。工作含同步范围清单、哈希基线的存放与更新、三态判定（仅本地改／仅远端改／两侧都改）、冲突的呈现与处理、写入前备份与部署失败回滚。

边界：

- 外壳负责本机目录与 iCloud 目录之间的搬运、原子写、基线与冲突判定；**合并与部署仍由 Rime 执行**，不自行解析或改写用户词典，避免与引擎的合并语义分叉。
- 首次读写 iCloud Drive 可能触发系统授权提示，须确认其时机不打断正在输入的文本。
- 开关默认关闭。开启、关闭和每次同步都不得中断当前组合；同步期间明确反馈输入是否仍然可用。
- 同步失败不改变本机数据，不静默降级，也不反复弹窗；错误进诊断记录，最近一次同步的状态在设置页可查。
- 触发方式：默认每 6 小时一次，外加启动时一次与设置页的「立即同步」按钮；间隔可调、定时可关。定时到点但正在输入组合或正在部署时延后到空闲；睡眠期间不补跑。
- 不新增常驻同步进程或后台服务。输入法本身常驻，定时器跑在输入法进程内即可，不为此单独起一个守护进程。

## 7. 验证与试用安排

每项功能在所属阶段完成有意义的检查，再进入下一阶段；避免最后才发现数据和事件模型不成立。

| 层次 | 检查重点 |
| --- | --- |
| 逻辑用例 | 全局索引、过期候选与触摸事件、部分组句、重复提交、配置应用失败、词典导入失败与恢复 |
| Rime 集成 | 固定方案产生真实候选、正常选择与学习、重启恢复、快照及文本往返；不把固定候选替身当引擎验收 |
| 云同步 | 两套独立数据目录（不同 `installation_id`）双向学词后合并收敛、同一词两侧都选过后权重不被清零、快照截断被拒绝并报错、关闭开关或断网不影响本机输入、删除云端目录不损坏本机库 |
| 系统接入 | TextEdit 与浏览器文本框先通过，再覆盖用户实际使用的终端和编辑器；验证标点、快捷键、焦点、跨应用提交、多屏定位 |
| Touch Bar | 实体设备上的点按、滑动、取消、组合变化、应用切换与系统显隐模式；与屏幕选择同词时结果一致 |
| 持续试用 | 从单一应用短时试用到日常使用；记录丢字、错选、重复上屏、卡顿、词汇重新找回及管理操作问题 |

架构已锁定 Apple Silicon，不构建 Intel、不做通用二进制。最低 macOS 版本不事先设定，由 M0/M1 的实际构建与运行验证后记录；“能编译”不代表该版本已兼容，Touch Bar 需求也不能被仅在无触控栏设备上运行所替代。

性能先在 M0/M1 记录同一测试序列下的 Rime 处理、窗口刷新和滚动耗时，M2 比较外壳新增开销。先报告可复现的测量结果，再确定阈值，不在当前缺乏测量时承诺固定毫秒数。记录应默认包含事件类别、耗时和错误，不包含实际输入正文或个人词条。

M5 的 7–14 天是建议观察窗口，不代表长周期学习效果已经被证明。有数据损坏、重复提交、跨应用串入或频繁丢字时，先修复再扩大试用范围。

## 8. 交付与开源准备

从 M1 起就保留清晰的开发构建、试用安装和回退步骤，最终整理成可重复执行的交付方式：

- 新输入法与鼠须管并存，保留恢复原输入法的路径；卸载程序和删除个人数据分开处理。启用过 iCloud 同步的用户，须说明云端快照的位置以及卸载不会自动删除它们。
- 固定源码与依赖版本，列出复用文件来源、资源和词库许可；按既定 GPLv3 方向准备新仓库材料，**建仓库时即在源文件头写入版权行**（`Copyright (C) 2026 EchoJamie <echojamieee@outlook.com>`，见[决策 5.4 节](decisions.md#54-项目标识版权与签名)），事后补要改动全部源文件。
- **首版只发布源码，不发布二进制。** 签名证书是免费的 Apple Development，只适用于本机开发与自用；向他人分发二进制需要 `Developer ID Application`（仅付费账号可得），也不能公证。这是证书条件的技术推论（[D-15](decisions.md#2-已确定的方向)），不是可选项。需要安装包的人自行构建。
- 首版采用手动下载源码与明确的构建、升级步骤；Sparkle 自动更新待首版稳定后再评估，不把更新服务引入第一轮核心开发。
- 2026-09-24 已建立本地仓库并完成首次提交；**远端仓库仍未创建、未推送，也未安装输入法**。实际交付时先准备可审阅的产物与操作清单，再按届时授权执行。
