# 架构与源码目录

本文供维护者定位代码和修改边界。Glint 是一个 InputMethodKit 服务进程：Rime 负责拼音解析、候选顺序、组句和学习；Glint 负责 macOS 会话、界面、资源安装与用户数据管理。没有插件市场或额外常驻守护进程。

## 目录

| 路径 | 职责 |
| --- | --- |
| `sources/App/` | 服务入口、产品 ID、输入源登记、串行维护队列及限量文件日志。 |
| `sources/Input/` | 每个文本客户端的输入会话、按键转换、预编辑与上屏。 |
| `sources/Engine/`、`sources/rime/` | Rime 的 Swift/C 边界、方案初始化和配置读取。 |
| `sources/Candidates/` | 屏幕候选窗和 Touch Bar 发布；两者消费同一轮 Rime 候选。 |
| `sources/Schemes/` | 已接入方案的清单、下载校验、安装和全拼／双拼配置。 |
| `sources/Data/` | 原子维护事务、个人／专业词库、迁移与外壳偏好。 |
| `sources/Sync/` | 可选的 iCloud Drive 文件同步、配置版本冲突与调度。 |
| `sources/Settings/` | 五页原生设置窗口。 |
| `installer/` | DMG 内独立身份的一次性原生安装器。 |
| `resources/`、`licenses/`、`scripts/` | Bundle 资源、许可证与可复现的构建／交付脚本。 |

所有 Swift 文件编成同一模块。目录表达职责，不伪装成彼此独立的框架。`Makefile` 明确只收录 `sources/*/*.swift`；C 桥接仍由根桥接头引入。新增文件应进入所属职责目录，不在 `sources/` 根下重新堆放。

产品 bundle ID 为 `com.github.echojamie.inputmethod.Glint`，可选简体模式 ID 为 `com.github.echojamie.inputmethod.Glint.Hans`；连接名为 `com.github.echojamie.inputmethod.Glint_Connection`。这些身份写在 `GlintIds.swift`、`Info.plist` 和本地化资源中，更改会影响系统已登记的输入源。构建前由 `make check-ids` 核对代码和 plist。

## 输入与候选

`Main` 持有 `IMKServer` 并运行服务。`GlintInputController` 每个宿主客户端各有 Rime session；Rime 的运行时属于进程，维护时只能有一个活动实例。激活新客户端先结束旧客户端组合，停用时消费已确认提交与剩余原始编码，再清除屏幕和 Touch Bar 状态。

按键经 `MacOSKeyCode` 转成 Rime/X11 键码；候选的顺序、文本、分页与最终选择仍以 Rime 为准。控制器只保存当前候选批次、全局索引、代次及面板浏览位置。任何点击、数字选择或 Touch Bar 确认都要回到同一 Rime session；组合变化使旧代次选择失效。屏幕排布可改变当前可见范围，但不能另造一份候选结果。

Touch Bar 桥接隔离在 `GlintTouchBar`。该宿主属性通道已在本机验证，公开 SDK 未承诺其协议稳定性；回调只返回文字时，同文异候选无法确定身份，必须拒绝歧义而非猜选。无硬件时只检测一次并跳过可选传输及会话预测，普通输入仍运行。具体交互见[输入行为](input-behavior.md)。

## 资源、维护与个人数据

内置雾凇资源以签名封存的 `rime.tar.gz` 随 App 提供，首次启动或顶层文件缺失时在同卷暂存、逐文件校验散列后补齐；已有用户配置和学习库不覆盖。万象按固定版本、大小及 SHA-256 从官方地址下载，校验后才解包；网络下载不占用 Rime 维护窗口。已安装方案存在用户目录，切换时读回实际部署配置，不维护第二份键位状态。

`GlintMaintenance` 等当前组合结束，再关闭 session 和运行时，串行执行部署、词库及同步任务。维护期间按键交还宿主。`GlintDataStore` 在隔离副本完成操作，仅提升指定目标；提升前保存 `before/`，先写恢复 journal，重启可回滚未完成替换。不要因表面代码重复而删掉这些顺序和核对。

方案切换会复制方案工作目录并保留事务备份，万象的大模型可能带来可观的临时磁盘占用。文件指纹按块读取，避免把大模型一次性载入内存；以后若优化副本机制，仍须保留崩溃恢复和外部修改检测。

`GlintPreferences` 只保存候选外观、当前方案与同步开关等外壳选项；Rime 标点、schema 和拼写规则仍由 Rime 的文件保存。专业词库面向雾凇主词典；鼠须管迁移只读源目录，活动数据库必须先锁定复制再在副本生成原生快照。数据路径与同步格式见[数据与同步](data-and-sync.md)。

## 修改原则

优先删除重复状态、旧约束与多余分支。只有现有职责确实容不下已确认功能时才新增类型。更改输入路径时同时核对客户端生命周期、候选代次与单次提交；更改用户数据时保留原文件、验证目标及中断恢复能力。设置窗口目前集中处理五页控件和回调，存储、下载与维护已在独立类型中；没有必要仅因行数拆出传递大量可变控件的薄包装。

## 开发约束

- IMK 回调、候选窗和设置控件在主线程操作；下载在 URLSession 队列执行，Rime 部署、词库和同步经同一维护队列串行化。输入回调不得等待文件日志或网络。
- 外部方案、个人词库和云端文件都视为不可信输入；校验格式、大小、路径、符号链接与版本后，才能进入隔离维护事务。用户目录里未知的配置字段要保留。
- 同一事实只保存一个权威状态：候选顺序与高亮读 Rime，方案键位读部署配置，界面只保留显示所需的代次与布局状态。不要为设置页另造一份持久状态。
- 文件注释解释跨系统边界和必须保留的安全条件；已结束的调查过程放进排障结论，不能留在代码里当执行指南。新依赖须固定版本、记录来源及许可证。
- 本轮按要求不增写测试代码。修改后仍需构建、静态校验和真实输入宿主验收；这些证据不能互相替代。
