# 排障与已踩过的坑

本文只保留能指导下次排查的判据、根因和处理原则。历史时刻、进程号、旧包哈希、临时截图与实验命令不随交付保留。先读[架构](architecture.md)与[数据边界](data-and-sync.md)，再按症状定位；不要直接清系统缓存或触碰 `~/Library/Rime`。

## 输入源可见，但切换或打字失败

1. **分层判定**：LaunchServices 能识别 App、TIS 列出输入源、菜单勾选、`IMKServer` 存活、宿主调用 `activateServer`、预编辑与上屏是不同证据。`TISRegisterInputSource` 返回成功或菜单勾选移动，不证明宿主真实输入成功。在前台 TextEdit 用实体键盘确认组合、候选和提交。
2. **标识与本地化**：本机曾观察到 bundle ID 不含 `.inputmethod.` 时系统扫描直接跳过；这是本项目在该环境的实测结论，不当作跨版本公开规范。`Info.plist`、Swift 常量、中文及英文 `InfoPlist.strings` 的输入源 ID 和显示名必须一致。缺英文回退时，菜单可能显示原始 ID 而不是“流光”。构建前的 `make check-ids` 防止漂移。
3. **父项与模式项**：`.Hans` 模式项可选，bundle ID 父项不可选却必须启用。父项未启用时，程序化选择曾返回 `-50`。第三方输入源通过系统设置添加；直接对它另调 `TISEnableInputSource` 曾同时写入旧名单，造成重复条目和菜单点击无效。
4. **重复副本**：构建包、备份或安装暂存件若以 `Glint.app` 留在可扫描位置，LaunchServices 可能记下同 bundle ID 的多个路径。安装脚本中新包与旧包的暂存件都不使用 `.app` 后缀，成功后删除暂存目录。先核对安装路径和系统设置，别反复注册或删除系统偏好数据库。
5. **入口与生命周期**：系统拉起输入法会传 `-psn` 等参数；不能把所有未知参数当 CLI 错误退出。`IMKServer` 必须强持有，否则进程可继续存在却不提供输入服务。创建失败须明确失败，不能留下空转进程。
6. **应用上下文**：同一输入源在 TextEdit 可用而在已运行的 Ghostty 不能切换，曾与旧应用进程和系统输入上下文有关。停止鼠须管后旧进程也未立即恢复，不能凭相关性断言鼠须管劫持。复查前台应用、旧／新进程和 ABC 切换行为。
7. **TIS 属性类型**：macOS SDK 的 `kTISPropertyIconImageURL` 值是 `CFURLRef`，不是 `CFStringRef`。判定记录是否来自安装副本时，要读取文件 URL 并比较解码后的完整 bundle 路径；只看 `Glint.app` 名称会误认构建包或备份。

## Rime、候选与界面

8. **C 结构体**：`RIME_STRUCT_INIT` 设置长度，但不保证其余字段清零。未先零初始化的 traits/context 曾导致崩溃。Swift 与 C 边界使用固定的全局候选索引，不能把页内索引直接当全局索引。
9. **预编辑光标**：Rime 返回 UTF-8 字节位置，AppKit 使用 UTF-16 选区。单给普通字符串曾被 IMK 宿主呈现为整段选中；现在传带组合样式的 attributed string 及明确的零长度插入点。改变按键导航时先保留拼音内部光标，再让末尾方向键浏览候选。
10. **候选身份**：候选文本相同并不代表同一候选。会话、组合代次和全局索引共同限制选择；部分组句后必须使旧选择失效。Rime 的已确认提交要消费一次，不能重复上屏。候选读取失败不能冒充“已经到末尾”。
11. **Touch Bar**：公开 `IMKCandidates.update()` 只刷新已有可见状态，不能单凭调用它推断触控栏会显示候选。本机实际采用宿主内部属性通道发布与撤回候选；属性 11 发布／撤回列表、属性 12 控制可见性；回调状态 1、2、3 分别用于高亮、确认与触摸结束。文字回传丢失身份时拒绝同文歧义。切源与上屏既要隐藏视图也要撤回宿主持有的旧候选列表。该通道在系统升级后必须复核，不能写成公开 API 保证。[Apple IMKCandidates](https://developer.apple.com/documentation/inputmethodkit/imkcandidates)。
12. **无 Touch Bar**：公开 AppKit 没有稳定的实体硬件查询接口；本机通过 IOKit 注册的 `touch-bar` 节点做一次性可用性判断。查不到时跳过可选传输并关闭当前会话预测，不等待、不轮询、不捕获异常后继续执行。它不能证明第三方 Rime 插件初始化完全没有运行。
13. **材质与布局**：非激活候选窗的 `NSVisualEffectView` 需用活动材质状态。让自绘文字整体参与 vibrancy 曾改变蓝色选中块颜色，因此保留系统材质背景与普通文字绘制。设置页 `NSBox.contentView` 改用 Auto Layout 后四边须显式约束；AX 控件存在不证明真实像素布局正确。

## 资源、维护与同步

14. **内置资源**：先把方案、插件、许可证和清单全部嵌入，再签 App；签后复制会破坏封存。构建必须拒绝缺少 `symbols_v.yaml` 等依赖的资源包。首次初始化在同卷暂存、校验后补齐，`default.yaml` 最后写入；已有配置和学习库绝不借补齐之名覆盖。
15. **下载与编码环境**：万象完整包通过固定大小和 SHA-256 后才解压。终端的 UTF-8 locale 与输入服务不同：非 UTF-8 环境下 `bsdtar` 曾把中文文件名列成八进制转义，导致路径检查误报。只给 tar 子进程指定 UTF-8 locale，不删除路径和符号链接校验。万象 Base ZIP 不含许可证，安装时另取固定版本的方案及模型许可证。
16. **配置解析**：Rime C 配置 API 会把路径里的 `/` 当层级分隔，不能无损读取 `speller/algebra` 这样的字面补丁键。现用 LibYAML 处理补丁并保留未知字段；重新序列化不会保留 YAML 注释和排版，事务备份保留原文。损坏 YAML 可能让 Rime 沿用旧编译结果，隔离部署前先验源并移除副本的旧 `build/`。
17. **学习库迁移**：Rime 原生 backup 在设备身份不一致时可能更新数据库元数据，不能在鼠须管源目录直接运行。活动库先锁定复制，对副本备份；Rime 的 TSV 导入会忽略坏行，需在外壳先做全量格式、条目和学习值核对。
18. **同步冲突**：第一次创建 `installation.yaml` 后还需更新一次 installation 信息，确保 `sync_dir` 指向本次隔离目录；一进程处理不同目录时不能沿用前一目录的设备 ID。配置预览之后本机或云端可能变化，确认时必须比对用户实际看到的版本。云端发布失败不得先提升本机数据。两机 iCloud 行为尚未验收。
19. **高频日志**：逐键、普通激活和触摸滑动日志曾过于密集，已移除。只保留启动、维护、下载、同步和关键异常；输入线程不等待文件 I/O。日志缺失并不能单独证明某个回调没发生。

20. **更新时退出旧版**：复制成功不代表运行中的旧版已经退出。[NSRunningApplication.terminate](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()) 只发送正常退出请求，必须再观察 `isTerminated`。安装器限定 bundle 身份与正式路径，异步等待退出后才替换；输入法维护中拒绝退出，超时不改成强杀。不要把“退出旧进程”交给普通用户，也不要以显示安装成功代替系统已启用输入源的判断。

21. **DMG 目录权限**：`mktemp -d` 创建的目录为 `0700`；直接用作 `hdiutil -srcfolder` 或源码 tar 的根目录，会把只允许创建者访问的权限带入交付物。即使说明文件本身为 `0644`、镜像与签名校验通过，也不能证明 TextEdit 等应用能正常打开它。打包统一在 `dist/.package/` 整理内容，以 `umask 022` 和普通 `mkdir` 创建目录，结束后清理。挂载后核对根目录为 `0755`、文件可读，并实际打开说明。不要要求用户修改只读卷的权限。
